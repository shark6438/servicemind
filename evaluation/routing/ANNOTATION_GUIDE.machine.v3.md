# 机器标注挑战集 v3

本轮由一个助手设计场景、编写问句并按场景意图给出结构化标签。它不是双人独立标注，
不是生产流量，也不计算或声称人工 Cohen's κ。v2 人工验证草案保持原状，本轮不替代其要求。
作者已见过旧规则、Jev 提示和旧实验输出，因此这是有明确研究目标的合成挑战集。

## 判据

按以下优先级标注：

1. 真正要求删除、抹除、销毁记录，关闭/解决工单，或者披露凭据，标为 unsupported。
   仅查询操作文档或明确否定执行，不因出现操作词而拒绝。
2. 除禁止操作外，request_write=true 或明确要求改动外部状态，标为 complex_workflow。
3. 只有记录编号、没有说明要做什么，标为 complex_workflow。
4. 同时需要记录数据和文档、故障诊断、推理或针对具体故障的处置，标为 complex_workflow。
5. 只读取一个已识别工单/支持记录的状态、负责人、优先级等字段，标为 simple_data_query。
6. 只检索指定主题的已有手册、清单、标准做法或规程，标为 simple_knowledge_query。

标签先于两侧预测冻结。Jev 仅接收问句和写入标志，不接收场景、标签、理由、split 或规则预测。
不因模型输出修改标签；标注缺陷如需更正，另存勘误并将本轮视为探索证据。

## 采样与限制

共 500 条，25 个业务主题，每主题五类现象、每类四种表达。两个集合为 200 条语义表达
挑战和 300 条基础设施场景挑战，均为合成数据。每类包含中英文，覆盖普通表述、同义改写、
复合意图、真实禁止操作，以及否定句/文档请求/信息不足/显式写入等边界。

主题内部的全部改写放在同一个 split：dev 240 条、test 260 条。主题按预先固定的摘要排序
分组切分。模板在主题间共享，所以 held-out topic 不等于 held-out wording；
测试是主题留出的模板化鲁棒性验证，不是独立自然语言泛化基准。

主要证据是 Jev 对规则在 test 上的配对差异；按主题做聚类 bootstrap 和组级配对置换检验。
逐例 McNemar 仅作描述性补充。混合臂只在 dev 上选一个阈值，并在 test 中固定。
历史 212 条是已暴露的参考数据，按原标签单独报告，不混入新 test。
