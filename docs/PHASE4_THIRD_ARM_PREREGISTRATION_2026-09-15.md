## 5. 门禁与判定规则（对 C1）

### 5.1 区间口径（先定义，避免 β 与分位数错配）

| 用途 | 检验类型 | 下界 LCB | 上界 UCB |
| --- | --- | --- | --- |
| 收益指标（Recall@5 ×2） | **双侧 95%** | 0.025 分位数 | 0.975 分位数 |
| 非劣指标（R@10 / MRR@10 / NDCG@10） | **单侧 95%** | **0.05 分位数** | 0.95 分位数 |

三者均由**配对自助（paired bootstrap，以 query 为重采样单位）**得到。
**必须注意：单侧 95% 的下界是 0.05 分位数，不是双侧区间的 0.025 下界**——后者对应的是
单侧 97.5%，与功效计算所用的 `z = 1.645` 不匹配。

### 5.2 门禁一：收益

| 子项 | PASS 判据 |
| --- | --- |
| 1a 全体 Recall@5 | LCB(0.025) **> 0** |
| 1b 困难集 Recall@5 | LCB(0.025) **> 0**（困难集按 §4 规则现算） |

### 5.3 门禁二：排序非劣

| 指标 | PASS 判据 |
| --- | --- |
| Recall@10 | LCB(0.05) **> −δ** |
| MRR@10 | LCB(0.05) **> −δ** |
| NDCG@10 | LCB(0.05) **> −δ** |

| 档位 | δ | 状态 |
| --- | ---: | --- |
| 当轮（本轮） | **0.020** | 生效 |
| Phase 7 | 0.005 | 未生效（需租户专家 qrels 或等规模新标注集） |

**δ 的语义是「企业愿意接受的最大质量损失」，不是可以为了凑功效而放宽的参数。**
把 δ 从 0.020 放宽到 0.030，等于声明 Recall@10 / MRR@10 / NDCG@10 中任何一项最多下降
3 个百分点仍可接受——在代理集的排序指标本就未达标的现实下，这与质量目标直接冲突。
**检验力不足的正确出口是 `INCONCLUSIVE`，不是降低标准。**

### 5.4 功效（逐指标，含联合）

数据：`evaluation/experiments/phase4_third_arm_2026-09-15/reports/prereg_power.json`
（脚本 `prereg_power_analysis.py`，仅在**已分析集合**上运行，属规划计算，不触碰留出集）。
锚点校验：C0 在开发集上重现 0.6857 / 0.7643 / 0.5848 / 0.6279。

**每个指标各用自己的配对差 SE，不得用 Recall@5 的 SE 代替其他指标。**

| 指标 | SE(dev, n=280) | SE(留出集, n=330) | 单指标功效 @δ=0.020 |
| --- | ---: | ---: | ---: |
| Recall@5（门禁一） | 0.01217 | 0.01121 | 0.556 |
| **Recall@10**（门禁二最弱项） | 0.01065 | 0.00981 | **0.653** |
| MRR@10 | 0.00591 | 0.00545 | 0.979 |
| NDCG@10 | 0.00570 | 0.00525 | 0.985 |

**门禁二的联合功效 = 0.688**（配对向量模拟 200,000 次，三项差向量共享重采样索引以保留
跨指标相关；残差相关 R@10↔MRR 0.283、R@10↔NDCG 0.641、MRR↔NDCG 0.916）。
三个边际功效的乘积为 0.629——**正相关使联合功效高于该乘积，但 0.688 仍须按「约七成」理解，
不得当作确定通过。**

以上功效均为 **H0（三项真实配对差恰为 0）** 下的通过概率。门禁一 1a 的功效取决于真实收益：
若真实收益等于开发集估计的 +0.0286，则 LCB(0.025) > 0 的功效约为 **0.72**；若真实收益为 0，
该判据的通过率即双侧 α 对应值 **2.5%**。

### 5.5 门禁三、四（本轮不做，登记为后续）

- **门禁三 运行成本**：p95 检索延迟增幅 ≤ 20%、GPU/索引容量与重建时间在预算内、
  跨 tenant/ACL/失效版本泄漏为 **0**。取证来源 = **受控 shadow**（无 qrels 也可测）。
- **门禁四 生成与弃答**：须用**真实 Reviewer 输出**测 answerable success、错误作答率、
  过度拒答率与 citation 正确性。**不得**用「金标是否在候选池内」代替。

**结论口径：**本协议只可能给出**门禁一、二**的正式裁定；即便双门禁通过，第三臂的状态
也只是 `RESEARCH_ACCEPTED / PRODUCTION_NOT_APPROVED`，必须再经 shadow 取证门禁三、四，
**不得直接生产采纳**。

## 7. 判定输出（三态）

对 C1 一次性输出：

```text
PASS:
  收益门禁（1a 与 1b）全部 LCB(0.025) > 0
  且三项非劣门禁的单侧 LCB(0.05) > -0.020

FAIL:
  任一收益指标的 UCB(0.975) <= 0
  或任一非劣指标的 UCB(0.95) <= -0.020

INCONCLUSIVE:
  其他所有情况，包括区间跨越 0 或 -0.020
```

**为什么 FAIL 需要「上界越过负向阈值」，而不是「下界低于负阈值」。**
一个形如 `[−0.03, +0.04]` 的区间只说明**证据不足**，它并不证明存在至少 2 个百分点的真实
损害——下界低于 −δ 只意味着「零效应无法排除」，与「损害已被证明」是两件不同的事。
把前者判成 FAIL，是把「未能证明非劣」误读为「已证明有害」。只有 UCB(0.95) ≤ −0.020，
即整个区间都落在 −δ 以下，才算证明了达到 δ 量级的损害。

**同理，`INCONCLUSIVE` 不得表述为「接近通过」或「差一点」。** 它与 FAIL 在**上线决策**上
等价（维持现役配置），但在研究结论上不同：它值得用更大的样本重做。

## 10. 已知局限（引用本协议结论时必须一并引用）

1. **门槛判据是外部 silver 代理集**（无租户专家签核），§4.1 的关闭门在这批数据上
   `applicable: false / passed: null`；本协议给的是**代理裁定**，不是生产放行。
2. **留出集偏小**：n=330 可答，门禁二联合功效约 **0.688**，门禁一（若真实收益 ≈ +0.0286）
   约 0.72。约三成的概率会因为样本量而非质量得到 `INCONCLUSIVE`。
3. **困难集由现役系统失败定义**（§4），存在选择偏差，只作目标子集指标。
4. **候选池覆盖率是 oracle 量**（两路 0.8714 → 三路 0.9143），只说明弃答门禁有理论空间，
   不能预测真实弃答率。
5. **成本与生成未测**（门禁三、四），本协议不覆盖。
6. **粒度效应未消融**：整篇文档 → 420 token 子块的收益从未被单独定价（见 §11 记录）。
