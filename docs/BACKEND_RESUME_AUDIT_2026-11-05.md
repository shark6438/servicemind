## 后续候选升级

### 1. 普通任务创建接口幂等：最优先

依据：[POST /runs](../src/servicemind/api.py) 当前没有普通请求的 `Idempotency-Key` 契约；
[create_run](../src/servicemind/persistence/repository.py) 每次生成新任务 UUID。
Webhook 和业务写入已有幂等，但浏览器超时重试普通任务时，仍可能创建多个 Agent 运行并重复花费。

建议以租户、用户和幂等键建立唯一约束，保存请求指纹与任务编号；容量检查与首次插入处在同一事务。
重试读取原任务前仍要验证访问权限，同键不同请求内容返回 409。可使用 PostgreSQL 唯一约束和
`INSERT ... ON CONFLICT` 处理竞争，不能只在应用中先查后插。
[PostgreSQL INSERT 文档](https://www.postgresql.org/docs/16/sql-insert.html)

验收目标：100 个并发相同键只创建一个任务；参数冲突返回 409；跨租户与跨用户不混用；
提交成功后响应丢失，重试仍得到同一个任务编号；队列满额不妨碍原请求重放。
这项可以使用模拟模型验证，新增模型费用为零，改造量较低。

### 2. 新 Worker 架构容量与故障对照：最适合补简历数字

已有[运行指标](../src/servicemind/observability/metrics.py)，但当前前后对照主要衡量数据库查询。
历史 [phase7_load_latest.md](../evaluation/reports/phase7_load_latest.md) 来自旧版本，且门禁为 FAIL，
不能证明新 Worker 架构的容量。

建议固定假模型和工具响应耗时，对比一、两个 Worker 在相同请求混合下的吞吐量、API 返回 202 的
P95、排队 P95、正常租户受突发租户影响的程度，以及积压消退情况。另在运行期间重启 API、
终止一个 Worker，记录恢复时间、重复调用与业务写入情况。

不预设吞吐一定翻倍；至少保留一个稳定运行窗口、机器资源、配置和原始观测。
这项不要求付费模型调用，工程投入低至中等。优先与请求幂等一起完成，再冻结一版。

### 3. 任务与 SSE 事件唤醒：有负载证据后推进

当前 [SSE](../src/servicemind/api.py) 每 0.5 秒读取事件和运行状态；空闲连接通常约产生
4 次 SELECT/秒，此外还有前端快照轮询。[Worker](../src/servicemind/orchestration/run_worker.py)
每次领取也会读取租户目录。小规模运行可以接受，高连接数需要实际测量。

可以用 PostgreSQL LISTEN/NOTIFY 唤醒，数据库任务与事件表继续作为可靠来源，并保留低频轮询补漏。
通知在事务提交后才发送；通知只作为唤醒信号，业务内容仍通过带权限检查和 RLS 的查询获取。
[PostgreSQL NOTIFY 文档](https://www.postgresql.org/docs/16/sql-notify.html)

验收目标：对比 100/500 空闲连接的数据库 QPS、CPU 和事件提交到接收的 P95；
监听断线后重新订阅并按游标补读，确认通知丢失不会造成事件丢失。改造量中等，模型费用为零。

### 4. 跨主机费用配额账本：多机部署时有价值

当前 Jev 的 [spend ledger](../src/servicemind/orchestration/jev_ledger.py) 使用本地 JSONL 与文件锁，
能协调同机共享文件的调用者。不同主机如果各用独立目录，将不能共同执行同一预算上限。

多机部署时可以改为 PostgreSQL 预留、结算和未知费用账本，配置租户日额度与全局额度，
保留超时及进程退出时的保守费用记录。验收应覆盖并发预留不超预算、重复结算、
崩溃后未知费用保留，以及逐条记录和账户用量对账。

模拟费用即可验证，不需要为测试消耗 Jev 额度。改造量中等；当前单机环境无需为技术栈增加而提前迁移。

### 5. Redis 共享缓存与并发合并：收益需要先证明

当前 [SemanticModelCache](../src/servicemind/model_gateway/cache.py) 是进程内字典，
缓存配置默认关闭；生产调用方目前也没有传入 `cache_allowed=True`。
因此不能写成已经落地了共享模型缓存，或声称已经节省了多少费用。

先测重复请求比例，再选择明确允许缓存的只读场景。接入 Redis 时沿用模型、提示词、schema、
租户和检索版本等缓存键，处理 TTL、权限变化与并发未命中合并。缓存命中不能跳过当前访问权限校验。

验收目标：并发同键只计算一次；跨租户不复用；权限、提示词和索引版本变化后不复用旧值；
报告实际命中率、模型请求减少量和 P95。改造量中等，收益取决于重复率，优先级低于前两项。
